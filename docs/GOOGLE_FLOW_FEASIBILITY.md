# Phase 7.6 — Google Flow feasibility

Reviewed November 12, 2026, using public Google documentation. No Google account, authenticated UI, credit or API call was used.

## Decision

**GO — manual Google Flow download and local import.** Google documents user-driven generation and download. Its help lists 50 daily Flow credits for eligible users, including non-subscribers. Credits are account-scoped and unused daily credits do not roll over. Eligibility, availability and rate limits vary. Omni Flash 1.2 currently lists six-second outputs at 6 credits for 360p or 18 for 720p. Veo 3.1 Lite lists 10 credits for most users at 720p. Costs are per output. Check the actual model, output count and price in the product before each generation. Five 360p Omni 1.2 clips would be 30 credits at the published rate, subject to availability and any retries. [Get started](https://support.google.com/flow/answer/16353333?hl=en) · [Credit rules](https://support.google.com/flow/answer/16526234?hl=en) · [Models and aspect ratios](https://support.google.com/flow/answer/16352836?hl=en)

**NO-GO — automated Flow UI or a Flow-credit integration.** The reviewed Google help documents the Flow Agent as an in-product collaborator. Its chat limits are separate from media generation credits. Flow Tools are built and used inside the product. I found no public third-party API for consuming Flow daily credits and no explicit authorization for the proposed browser automation. Google's general terms prohibit bypassing protective measures and automated access that violates machine-readable instructions. They do not establish permission to automate authenticated Flow generation. The old Generative AI Additional Terms page says its terms generally no longer apply since May 22, 2024. Use the current Google Terms and applicable prohibited-use policy. The prototype has no browser control, private endpoint, session cookie, account switching or remote credential flow. [Flow Agent](https://support.google.com/flow/answer/17093911?hl=en) · [Flow Tools](https://support.google.com/flow/answer/17104535?hl=en) · [Google Terms](https://policies.google.com/terms) · [Generative AI prohibited use](https://policies.google.com/terms/generative-ai/use-policy) · [Additional terms status](https://policies.google.com/terms/generative-ai)

## Local manual acceptance

1. Start the backend with `FLOW_GOOGLE_FLOW_MANUAL=1` and Uvicorn `--host 127.0.0.1 --no-proxy-headers`. The guide and strict import are disabled by default. The regular MP4 import still works.
2. Prepare a 30-second vertical Studio project with a six-second scene and an existing baseline export. Open **Google Flow manual feasibility**. Copy the sample prompt into Google Flow yourself. Confirm one output, six seconds, portrait 9:16, model, cost, credit balance and visible watermark settings before taking any generation action. Stop if the model or expected cost is unavailable. [Google's video workflow](https://support.google.com/flow/answer/16353334) · [Watermark rules](https://support.google.com/flow/answer/16353333?hl=en)
3. Use the asset menu to download a video file. Keep the original and its watermarks. Select the matching scene and enable the manual Flow check before import. The validator checks MP4, H.264/HEVC, coded portrait 9:16, six seconds within 0.15s and decoded frame changes. Rotated landscape-coded files are outside this strict guide. Frame changes do not establish provenance or guarantee meaningful motion. Inspect the source and exported clips visually. The local tool does not verify invisible SynthID, and its preservation after encoding is unverified. [Google's download workflow](https://support.google.com/flow/answer/16935308?hl=en)
4. Review the resulting vertical export and approve the exact MP4 if suitable. Studio still uses a mock narration tone. The guide's importing, completed and failed states follow the existing operation-verified local import queue. Cancellation stops the queue and preserves previous approvals.

## Official paid fallback design

Use stable `gemini-omni-1.2-flash`, documented on the Gemini Developer API paid tier. Google's current Veo guide lists the Gemini API Veo 3.1 Preview shutdown on October 22, 2026. The future adapter would use the official Google Gen AI SDK `client.interactions.create` with a text prompt and `response_format={type: "video", aspect_ratio: "9:16", duration: "6s", resolution: "720p"}`. The official guide documents portrait output and whole-second durations from 3 to 15 seconds. For REST, use documented Interactions responses, which carry MP4 video data in model-output steps. Use the existing staged MP4 validator and project asset commit for returned bytes. [Model availability](https://aistudio.google.com/docs/models/gemini-omni-flash) · [Official SDK and REST guide](https://aistudio.google.com/docs/omni) · [Veo status](https://aistudio.google.com/docs/veo) · [Gemini API terms](https://aistudio.google.com/docs/terms)

720p video output at 5,792 tokens per second and $12 per million video output tokens is about $0.417 for six seconds or $2.09 for five, before other billed tokens. No free tier is listed for this model. Flow credits are a separate product balance. No verified mechanism lets them pay Gemini API charges. [Gemini pricing](https://aistudio.google.com/docs/pricing#gemini-omni-1.2-flash)

The current adapter is preflight-only, disabled unless `FLOW_GEMINI_VIDEO_PREFLIGHT=1`. It checks presence of a server-side `GEMINI_API_KEY`, explicit consent and `FLOW_GEMINI_VIDEO_MAX_USD` against a $1 planning reservation per six-second video. The default cap is $0. The planning allowance is not a billing guarantee. No credential is needed for the manual guide and no paid transport or consent endpoint exists. Before enabling a future transport, bind consent to a specific project, scene, prompt, quote and single generation. Reserve budget atomically before submission and keep uncertain charges reserved until reconciled. Never retry a possibly accepted generation automatically. Revalidate pricing, account access and enforceable usage ceilings first.
